## Overview

This project is a small Python utility that reads questions from a locally
saved HTML quiz page and compares them with a locally stored question catalogue.
It uses fuzzy string matching to find the catalogue entry that most closely
resembles each extracted question, then prints the corresponding catalogue
answer and available explanation.

The project is intended to help with:

- studying question wording;
- inspecting and testing HTML extraction logic;
- comparing a saved quiz page with a personal study catalogue; and
- experimenting with Python, HTML parsing, and fuzzy matching.

It is **not** a substitute for learning the applicable rules, consulting
official DBB materials, or completing an assessment independently.

## How it works

The current script performs these steps:

1. Loads `questions.json` from the current working directory.
2. Loads `test.html` from the current working directory.
3. Parses the HTML with BeautifulSoup.
4. Extracts text from Moodle-style `div.que div.qtext` elements inside
   `div#page`.
5. Normalizes question text by lowercasing it, removing punctuation, and
   collapsing whitespace.
6. Compares each extracted question with every catalogue question using
   `rapidfuzz`.
7. Prints the best matching catalogue answer and any available explanation.

The matching process is approximate. A high similarity score does not prove
that the match is correct, and the current script does not display a confidence
threshold or ask for confirmation before printing a result.

## Requirements

- Python 3.14 or newer, as specified in `pyproject.toml`;
- the dependencies declared in `pyproject.toml`;
- a locally saved HTML file named `test.html`; and
- a locally maintained `questions.json` file in the expected format.

The project currently declares these Python packages:

- `beautifulsoup4` for HTML parsing;
- `rapidfuzz` for fuzzy matching;
- `requests` for the unused HTTP helper; and
- `pymupdf` for the separate PDF catalogue tooling.

## Installation

### Using `uv`

From the repository directory:

```bash
uv sync
```

Run the interactive CLI with:

```bash
uv run anschreiber-helper
```

The CLI asks whether to use the local `test.html` file or the browser
workflow. You can also select a mode directly:

```bash
uv run anschreiber-helper --manual
uv run anschreiber-helper --automated
```

Use `--help` to see all options. For custom file locations:

```bash
uv run anschreiber-helper --manual --html /path/to/test.html \
  --catalogue /path/to/questions.json
```

### Using a virtual environment and `pip`

Create and activate a virtual environment with Python 3.14 or newer, then
install the project:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

On Windows PowerShell, activation is:

```powershell
.venv\Scripts\Activate.ps1
```

Then run:

```bash
anschreiber-helper
```

If the command is not available after installation, run `python main.py`
instead.

Do not copy credentials, cookies, session tokens, or other secrets into this
repository.

## Input files

### `test.html`

`test.html` is expected to contain the HTML that the parser is authorized to
process. The current extractor expects a container with this structure:

```html
<div id="page">
  <div class="que">
    <div class="qtext">Question text</div>
  </div>
</div>
```

The script reads this file locally; it does not need to log in to a website.
Do not save or commit HTML containing personal data, private URLs, session
tokens, hidden form values, or other confidential information.

### `questions.json`

The catalogue is expected to be a JSON array with entries similar to:

```json
[
  {
    "id": "K-1",
    "question": "Example question?",
    "answer": "Ja",
    "article": "Example rule reference",
    "explanation": "Example explanation."
  }
]
```

Catalogue content should come from sources that you are permitted to use.
Before relying on an entry, check it against the current official source.

## Output

The program prints a numbered list containing:

- the extracted question;
- the best matching catalogue answer; and
- an explanation when one is present in the catalogue.

The output should be treated as a study aid and review prompt, not as an
authoritative decision or an automatically correct assessment response.

## Limitations and known risks

- Fuzzy matching can select a similar but incorrect question.
- Small wording changes, negations, numbers, names, and rule references can
  materially change the correct answer.
- The script currently selects the highest-scoring match without a minimum
  score or ambiguity check.
- HTML structure changes can result in missing questions or parsing errors.
- The script uses files relative to the current working directory.
- Catalogue entries can become outdated as rules and assessment questions
  change.
- The script currently prints the catalogue answer even when the match has not
  been independently verified.

For reliable study, review every match manually and consult the current
official rules and training materials.

## Privacy and security

## Development notes

The main implementation is in `main.py`. The repository also contains
supporting catalogue-generation code in `pdf_to_json.py`. Changes to the HTML
format, JSON schema, matching algorithm, or output format should be tested with
representative, non-sensitive fixtures.

Before submitting changes, run the script against a local fixture and verify
that:

- the expected number of questions is extracted;
- question order is preserved;
- catalogue fields are loaded correctly;
- unmatched or ambiguous questions are handled safely; and
- no private input data is included in the change.
